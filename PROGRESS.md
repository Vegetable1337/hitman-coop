# Прогресс Hitman 3 Co-op

## Steam-приглашения

Сборка для Steam создаёт приватное лобби на двух игроков и открывает окно приглашений в оверлее. После принятия приглашения мод использует Steam Networking Messages, чтобы передать пакеты существующего кооперативного протокола. Пакеты принимаются только от второго участника текущего лобби. Для этого режима свой UDP-порт на роутере настраивать не нужно.

На Steam-версии HITMAN 3.290.1 мод получил успешный результат создания лобби под App ID 1659040, начал ожидание игрока и завершил сессию по команде выхода. Подключение второго аккаунта и синхронизацию миссии по этому транспорту ещё предстоит проверить.

## Этап 1. Версии, SDK и установка

- Локальная Steam-версия `Retail\HITMAN3.exe` имеет версию 3.290.1.0. [ZHMModSDK 4.2.1](https://github.com/OrfeasZ/ZHMModSDK/releases/tag/v4.2.1) относится к ветке SDK для этой версии игры. Код SDK распространяется по GPL-3.0 или более поздней версии.
- В [Hitmen](https://github.com/OrfeasZ/ZHMModSDK/blob/v4.2.1/Mods/Hitmen/Src/Hitmen.cpp) есть Steam Networking Sockets и поиск второго `ZHitman5` в отдельном блоке сцены. В `OnFrameUpdate` вызовы периодической отправки движения и NPC закомментированы. Это исходник эксперимента.
- Взял за основу [HITMAN Co-op 0.14.0](https://github.com/JordanRodrigues021/hitman-coop/releases/tag/v0.14.0), лицензия GPL-3.0-or-later. `plugin/Src/HitmanCoop.cpp` регистрирует DLL через `DEFINE_ZHM_PLUGIN`. `PartnerPuppet.cpp` размещает отдельную сущность через `ZSpatialEntity::SetObjectToWorldMatrixFromEditor`, а `HitmanCoopUi.cpp` содержит игровой интерфейс.
- В `Hitman3Coop` лежит локальная копия исходников. В `Hitman3Coop/_dist/HitmanCoop-0.14.0` лежит распакованный релиз автора. Перед распаковкой сверил SHA-256 архива `7ba64e1f6e7ac5c0a95909c7ac9e49520763c9a1c684508618f96c1eb4dd1697`.
- Установщик релиза добавил SDK, DLL мода и манифест в `Retail`. Проверка коллизий показала, что файлы установщика отсутствовали до установки. Настройку игры из графического установщика и правило брандмауэра не применял. В `Retail\mods\HitmanCoop.ini` отключил автообновление для воспроизводимости.
- Прямой запуск `HITMAN3.exe` до меню завершился с кодом 0 как с загрузчиком, так и без него. При последующем запуске через Steam появился игровой процесс и мод вывел сообщение о готовности в `Retail\mods\HitmanCoop.log`. Журнал зафиксировал работу игрового цикла. В журнале SDK есть предупреждения о хуке EOS и установке обработчика исключений. Загрузка игровой миссии ещё требует проверки.
- Для первоначальной установки использовал DLL автора. Пересобрал плагин из исходников с MSVC 19.44.35230, Windows SDK 10.0.26100 и CMake/Ninja. Результат находится в `_build/msvc-x64/install/mods/HitmanCoop.dll`. Проверены три обязательных экспорта, все 57 импортов SDK и совпадение ABI 1 с установленным ZHMModSDK 4.2.1. Сборка также прошла 97 тестов ядра. В `tools/check-dll.ps1` добавил поиск `dumpbin.exe` из активного окружения и учёл системную `IPHLPAPI.dll`, которая нужна для определения адресов адаптеров.
- После игрового теста повторно проверил PowerShell-установщик в двух отдельных тестовых каталогах. Все 6 проверок прошли на версиях 3.290.1 и 3.280.0. Установщик выбирает нужную пару DLL, сохраняет существующий мод и при удалении восстанавливает исходные файлы побайтно. Отчёт сохранён в `_build/installers-20261118-155557/report.md`.

## Этап 2. Два процесса

- Два экземпляра релизной утилиты `Test-Connection.exe` обменялись пакетами между Host и Client через `127.0.0.1:47049` с выключенным ретранслятором. Оба подтвердили связь, общую тестовую сцену, получение движения напарника и подтверждение тестового события хостом. После завершения хост получил уведомление об отключении.
- Релизная утилита у клиента вышла с кодом 1. Она сравнивает число NPC, полученных от хоста, со всеми восемью NPC тестовой сцены. При этом журнал подтверждает передачу управления частью NPC клиенту. Бинарник вывел 3 из 8, а проверка рассинхронизации на хосте в том же сеансе зафиксировала восемь NPC в одинаковых позициях до тестового события.
- В `core/nettest/NetTest.cpp` заменил подсчёт принятых от хоста снимков на существующую проверку всей сцены. Хост и клиент должны подтвердить, что все восемь NPC имеют одинаковое состояние и находятся в пределах одного метра от своего аналога на другой стороне. Изменение относится к отдельной диагностической утилите.
- Собрал сетевое ядро и диагностическую утилиту на Windows через Zig 0.15.2 (Clang, C++20). Все 97 тестов ядра прошли. Исправленная утилита в двух отдельных процессах подтвердила движение напарника, согласованное состояние всех восьми NPC и подтверждение тестового события хостом. Все четыре проверки прошли у Host и Client. Журналы сохранены в `_build/local-gnu/core-tests.log`, `_build/local-gnu/host.log` и `_build/local-gnu/client.log`.
- Повторный прогон `netsim` с 60 мс задержки в каждую сторону, джиттером и 3% заданных потерь завершился с кодом 0. Прошли 13 проверок из 13, включая получение кода подключения, передачу NPC клиенту и возврат управления хосту, а также отключение. Отчёт сохранён в `_build/relay-netsim-verified/report.md`. Для повторения добавил в `tools/gametest/gametest.py` параметр `--nettest` и выделил тесту UDP-порт 47198 для подставного хоста.
- Транспорт в выбранном проекте реализован на UDP/Winsock. Код ядра содержит версию протокола 18, декодирование сообщений, интерполяцию, подтверждения и повторную отправку. Локальный прогон подтверждает только обмен в тестовой сцене.

## Этапы 3 и 4. Игровая проверка

На Steam 3.290.1.0 запустил «Свободную тренировку» в настоящей игре и подключил локального бота через ретранслятор. Канал диагностики подтвердил, что появился отдельный активный, видимый движку актор напарника. Между двумя отсчётами его координаты изменились на 4,15 м, координаты управляемого агента совпали. Хост и бот в одном замере согласовали позиции всех 83 NPC. После теста игра закрылась штатно, настройки мода восстановлены побайтно.

В первом игровом прогоне прошли 14 из 19 проверок. Счётчики пропуска ИИ и коррекции ориентации NPC остались нулевыми. Перед проверкой отключения потока NPC сценарий переместил хоста ближе к боту, после чего управление NPC вернулось хосту. В момент проверки у бота уже было ноль NPC, поэтому сценарий завершился по тайм-ауту до перезапуска миссии. Отчёт и телеметрия сохранены в `_build/ingame-20261118-153919`.

Убрал перемещение хоста из сценария передачи NPC и добавил отдельную проверку движения модели. После команды перезапуска сценарий теперь ждёт новую запись о синхронизации. Повторный игровой прогон прошёл **28 из 28** проверок. Модель сместилась на 4,10 м при неподвижном локальном агенте. Подтверждены передача 82 NPC боту, отключение локального ИИ у ведомых NPC, коррекция ориентации, возврат NPC хосту при прекращении потока, повторная синхронизация после перезапуска и удаление модели при отключении бота. Отчёт сохранён в `_build/ingame-20261118-154558/report.md`. Бот передаёт координаты NPC, поэтому синхронизация поз скелета между двумя игровыми клиентами остаётся открытой проверкой.

Отдельный игровой прогон взаимодействий прошёл **19 из 20** проверок. Подтверждены повторная выдача и снятие предметов у модели напарника, перемещение тел и их перетаскивание по потоку координат бота. Проверка фильтра повторяющихся событий осталась открытой. Игра нашла 268 взаимодействий, из них 74 поддерживаются репликацией, но за время наблюдения счётчик событий был нулевым. Отчёт сохранён в `_build/interactions-20261118-155100/report.md`.

В Steam временно запустил локально собранную DLL с SHA-256 `793a9898692977b8c980ae5376dc1bfe5a6f10b7cb154fe8492a6fd213f0ec98`. Бот подключился напрямую к `127.0.0.1:47047`, синхронизировал «Свободную тренировку» и сместил свой актор на 4,12 м при неподвижном локальном агенте. После отключения актор был удалён. Все 7 проверок прошли, игра закрылась штатно, исходные DLL, файл символов и настройки восстановлены побайтно. Отчёт сохранён в `_build/direct-ingame-20261118-160142/report.md`.

Два реальных игрока в одной миссии ещё требуют проверки. Репликация удерживаемого предмета и состояний NPC уже имеет игровую проверку, а отдельный сетевой путь для выстрела и промежуточного урона ещё не подтверждён. В SDK 4.2.1 есть хук `ZHM5ItemWeapon_FireProjectiles`. Следующий эксперимент для стрельбы должен проверить, какие вызовы хука относятся к локальному игроку, и отдельно измерить эффекты выстрела и авторитетное изменение состояния NPC.

В текущих исходниках `ContractEnd` открывает локальный экран итогов. По исходникам пока не подтверждён механизм, который завершает миссию на обоих клиентах одним игровым действием. Для каждого сценария ниже сначала запишите версию игры и мода на обоих ПК, миссию и точку старта.

| Сценарий | Что должно произойти |
| --- | --- |
| Движение и анимация | Оба видят отдельную модель напарника. По очереди пройдите несколько метров, развернитесь, присядьте и встаньте. |
| Оружие и стрельба | Гость достаёт, использует и убирает игровое оружие. Хост проверяет видимое состояние и реакцию общего NPC. |
| Урон и состояние NPC | Один игрок меняет состояние NPC. Второй сверяет результат для того же NPC. |
| Предметы | Гость подбирает предмет. Хост проверяет его исчезновение из мира. |
| Маскировка | Гость меняет маскировку на обычный костюм NPC. Хост сверяет внешний вид модели. |
| Тревога и тела | Вызовите тревогу, затем переместите и спрячьте тело. Сверьте состояние у обоих игроков на каждом шаге. |
| Цель и выход | Один игрок завершает цель. Второй сверяет её отметку. Затем оба проверяют состояние миссии при выходе. |
| Отключение | Гость нажимает Leave. Модель исчезает, хост остаётся в миссии. |

Следующий игровой прогон начинается с движения отдельной модели. Автор указывает, что модель напарника неуязвима и невидима для ИИ, а урон своему персонажу каждый принимает в своей игре. Полная общая симуляция персонажей и прохождение миссий требуют проверки на реальных клиентах.
